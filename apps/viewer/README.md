# @swarmcast/viewer

Static pages served by the public server: `join.html` (nickname form, browser check), `watch.html` (player) and `invalid.html` (expired or invalid link), in English and Brazilian Portuguese, on the Forest & Cream brand (`@swarmcast/shared/web/brand.css`). They contain no inline styles and one inline script, the startup guard that the build writes into `join.html` and `watch.html` (`@swarmcast/shared/web/startup-guard`: a page whose own script failed to load reloads itself, at most three times in a row); the server allows exactly that script by its SHA-256, so the strict CSP holds (no `'unsafe-inline'`).

- Build: `npm run build -w @swarmcast/viewer` → `dist/`, served from `web/viewer` in release packages.
- Tested through the server's Playwright suite (`npm run test:e2e`, including `adaptive-delay.spec.ts` and `chat.spec.ts`), unit tests in `test/unit/` (`npm test`) and the chat UI suite in `test/chat/`: Playwright against a mock hub and the built page, in every engine and on phones (`npm run build -w @swarmcast/viewer`, then `npx playwright test -c apps/viewer/test/chat/playwright.config.ts`). `npm run dev -w @swarmcast/viewer` alone has no backend, so run the server for real testing.
- Key files in `src/`:
  - `watch.ts`: hls.js + p2p-media-loader setup, "Stable" (the default) or "Lower delay" profile, P2P off by default (opt-in; a viewer who turns it on keeps it on), "Go live" button, the "~14 s behind live" status, control channel.
  - `latency-controller.ts` (pure, unit tested in `test/unit/`) and `adaptive-delay.ts` (wiring): the **adaptive delay**. Each viewer's target delay adapts to their connection: Stable starts at 20 s and drifts down to 10–12 s on a firm network (12 s while P2P is on and peers deliver) or up to 30 s on an unstable one; Lower delay moves between 6 and 10 s. Inputs: segment load times vs segment duration, bandwidth estimate variance, stalls, the buffer trend, HTTP vs P2P segments. Bounds: `ADAPTIVE_DELAY` in `packages/shared/src/playback.ts`, capped by `MAX_PLAYER_DELAY_S` (`packages/shared/src/constants.ts`). `?delaySpeed=10` on the watch page runs the controller's clocks 10× faster (tests only: honoured only when the server runs with `SWARMCAST_TEST_HOOKS=1`, as the E2E harness does). Details: [docs/QUALITY.md](../../docs/QUALITY.md#adaptive-delay).
  - `quality-menu.ts`, `latency-toggle.ts`, `player-config.ts`: the quality menu (Auto or one rendition), the Stable / Lower delay switch and the player settings ([docs/QUALITY.md](../../docs/QUALITY.md)).
  - `integrity.ts`: verifies the Ed25519-signed manifest and checks every P2P segment's SHA-256.
  - `wake-lock.ts`, `media-session.ts`, `share.ts` (pure controllers with the browser APIs passed in, unit tested): keep the screen on while playing (Screen Wake Lock, asked for again when the page is visible again; `block('audio-only')` lets go), lock-screen play / pause with the streamer's name and avatar (as a `data:` URL the page reads itself), and the Share button (share sheet, else clipboard, else a selected field), whose link comes from `GET /api/share` only for viewers of the current link.
  - `peer-guard.ts`: closes connections to blocked peers by matching ICE ufrags from tracker signaling.
  - `join.ts` wires `join-form.ts` (the nickname form, testable with its page, fetch, solver and navigation passed in); `pow.ts` + `pow-worker.ts` + `pow-attempts.ts`: the proof-of-work browser check (on by default, remembered per browser), with its progress bar; a worker that stays silent for 15 s falls back to the main thread.
  - `tracker-mux.ts` (installed first by `peer-guard-install.ts`): the P2P tracker connection carried inside the `/control` WebSocket, so a viewer holds one socket.
  - `p2p-fallback.ts` and `stall-recovery.ts`: P2P can never starve playback (a stuck peer fragment is fetched over HTTP) and the player never stays stuck outside what it can load.
  - `chat/`: the chat, a lazy chunk loaded by `chat/loader.ts` only when the live has the chat on: `session.ts` (protocol state, resume after a reconnect), `render.ts` (untrusted text through `textContent` only; ESLint refuses `innerHTML` in this folder), the input, the emoji and emote picker (emoji data built by `scripts/emoji-data.mjs`) and the GIF picker (asks the viewer first). [docs/CHAT.md](../../docs/CHAT.md).
  - `branding/`: "Your page" (`brand.ts`, loaded by `branding/loader.ts`; `join-brand.ts` on the join page; `pix-sheet.ts`, the Pix support sheet). A failure leaves the stock page. [docs/BRANDING.md](../../docs/BRANDING.md).
  - `i18n.ts` and `invalid.ts`: the pages' language and the "link not valid" page.
