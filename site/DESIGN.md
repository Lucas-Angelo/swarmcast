# SwarmCast site: design spec

The site must look like a calm, credible product site (think Tailscale, Obsidian, Linear, Signal,
the OBS download page) and never like a sketchy download page. Audience: non-technical streamers,
mostly in Brazil, mostly on Windows.

## Principles

1. **Calm colour.** Cream page, ink text, one primary (pine teal) for the action and links, honey
   only as a small warm highlight.
2. **Flat.** 1 px borders, small radii, no glows, no gradients, no neon, no drop shadows on buttons.
3. **One thing per screen.** One primary action (download), one headline, one supporting line.
4. **Show, don't claim.** Real screenshots of the app in clean frames, honest limits in plain words.
5. **Readable.** ~70 characters per line in prose, 1.6–1.7 line height, generous whitespace.

## Tokens (one place)

All colours, fonts, radii and shadows come from the brand tokens, `assets/brand/tokens.css` (repo
root, generated by the brand tools and shared with the panel and the desktop app; never edited
from the site). Default palette: **Forest & Cream** (cream page, pine-teal primary, honey
secondary). The site layers on top, in `site/src/styles/tokens.css`:

- the font files (self-hosted Inter; Fredoka from `assets/brand/font/`, subset to Latin woff2 in
  `site/src/fonts/`);
- aliases `--sc-radius` (= `--sc-radius-md`) and `--sc-shadow-sm`, and the layout scale below.

Body text (`--sc-text`), `--sc-border-strong`, `--sc-accent-soft`, `--sc-on-danger`, `--sc-font-text`
(Inter, then the UI stack) and `--sc-font-mono` are brand tokens too: the site uses them as they are and
never overrides them.

`site/src/styles/starlight.css` maps Starlight's `--sl-*` variables onto these, so the docs follow
the same palette in light and dark. Nothing else in the site hard-codes a colour.

| Brand token | Use on the site |
|---|---|
| `--sc-bg` | Page background (cream) |
| `--sc-surface` | Raised things: cards, frames, alternate section bands |
| `--sc-surface-2` | Hover fills, table heads, the frame title bar |
| `--sc-border` | Hairlines (1 px) |
| `--sc-ink` | Headings, strong text |
| `--sc-muted` | Secondary text, captions, meta lines |
| `--sc-accent` / `--sc-on-accent` | Primary button, focus of the brand (pine teal) |
| `--sc-accent-strong` | Links and accent text (AA on `--sc-bg` and `--sc-surface`) |
| `--sc-secondary` / `--sc-on-secondary` | Honey: fills only (logo mark, "Your system" badge) |
| `--sc-success`, `--sc-warning`, `--sc-live`, `--sc-danger` | Status only (asides) |
| `--sc-focus` | Focus ring (2 px, offset 2 px) |
| `--sc-radius-sm` / `-md` / `-lg` | 6 / 10 / 16 px |
| `--sc-shadow` | `none`: the site is flat |
| `--sc-font` | Fredoka: the wordmark only (it reads childish at headline sizes) |
| `--sc-font-ui` | System UI stack, the fallback under Inter |

`site/test/unit/tokens.test.ts` checks that every token above exists and that text pairs meet
WCAG AA in light and dark, so a new palette cannot silently break contrast.

## Type

Inter Variable for all text, self-hosted from `@fontsource-variable/inter` (no request to Google
Fonts). Fredoka (the brand face) only for the "SwarmCast" wordmark next to the mark.

## Space and layout

- 4 px base: 4, 8, 12, 16, 24, 32, 48, 64, 96, 128.
- Container 1120 px max; gutters 16 px (phone), 24 px (tablet), 32 px (desktop).
- Sections: 96 px vertical padding on desktop, 64 px on phones. A section is title + one-line lead +
  content; title and lead centred on the landing page, left-aligned elsewhere.
- Prose max width 70ch (`--sl-content-width: 46rem` in the docs).

## Components

- **Nav**: 64 px, sticky, `--sc-bg` with a bottom hairline. Logo left; Guide, Download, GitHub,
  language right. Phones: logo, Guide, language, GitHub icon.
- **Button**: 44 px (large 48 px) high, `--sc-radius`, 15–16 px semibold. Primary = `--sc-accent`
  fill; secondary = `--sc-surface` fill + `--sc-border-strong` border. Hover: a darker teal / `--sc-surface-2`
  fill. No shadows, no pills, no icons except a 18 px download arrow.
- **Download block** (hero): one primary button for the detected system, one muted meta line
  (version · size · system), one line of quiet links (alternative file, Other platforms, How to
  install), one trust line (Open source · MIT · No account). Phones: "open this page on your
  computer" with Copy link / Share.
- **Frame**: a screenshot inside a 1 px bordered box, `--sc-radius-lg`, with a 36 px neutral title
  bar (three grey dots + app name). No perspective, no tilt, no glow.
- **Card**: `--sc-surface` fill, 1 px `--sc-border`, `--sc-radius-lg`, 24 px padding. Hover only when
  the whole card is a link (border turns `--sc-border-strong`).
- **Feature grid**: 3 × 2 cells separated by hairlines (no individual card borders), a 20 px line
  icon, title, two lines of text.
- **Steps**: numbered (01–04) in `--sc-muted` tabular figures, a 40 px icon tile with a 1 px border,
  title, one line.
- **Aside (docs)**: `--sc-surface` fill, 1 px border, 3 px left border in the status colour.
- **Code**: `--sc-surface` background, 1 px border, `--sc-radius`, mono 14 px.
- **Icons**: 1.5 px stroke line icons, 20–24 px, `currentColor`. No emoji, no clip art.

## Do

- Keep exactly one primary (teal) button per view.
- Use `--sc-muted` for everything secondary; keep body text `--sc-text`.
- Explain security warnings calmly, with the exact button names the system shows.
- Check every page at 360 px wide in light and dark.

## Don't

- No purple, indigo or violet, no blue-to-purple gradients, no glow or coloured shadows.
- No pill-shaped mega buttons, no stacks of underlined links, no "100% safe!" badges.
- No generic node-graph or network clip art.
- No third-party requests (fonts, analytics, CDNs).
- Never set a colour outside `assets/brand/tokens.css` (derive with `color-mix()` instead).
