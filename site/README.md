# SwarmCast website

The website at <https://lucas-angelo.github.io/swarmcast/>: the landing page, the download page and the
**only guide for streamers and viewers** (install, OBS, going live, protection, updates, uninstall,
troubleshooting), in English and Brazilian Portuguese. The offline guide inside the installer zips is
generated from the same pages, and the panel's "Help" link points here.

Built with [Astro](https://astro.build/) + [Starlight](https://starlight.astro.build/). It is a
standalone project with its own `package-lock.json`, not a root workspace, so the app's builds never
install Astro. No trackers, no cookies and no third-party requests: fonts and images are self-hosted.
Design rules: [DESIGN.md](DESIGN.md).

## Run, build, test

Node 24.

```sh
cd site
npm ci
npm run dev        # http://localhost:4321/swarmcast/ (live reload)
npm run check      # astro check: types of the components, lib/ and the unit tests
npm run build      # site/dist/; fails on a broken internal link (starlight-links-validator)
npm run preview    # serves the build
npm run test:e2e   # Playwright (Chromium) against the BUILT site; SITE_E2E_PORT moves its port (default 43210)
```

- **Unit tests** (`test/unit/`: the download picker, the stats reader, the brand tokens and their
  contrast) run with the root vitest: `npx vitest run site/test/unit` from the repository root (or
  `npm test`, which includes them). They need the root `npm ci`.
- **E2E tests** (`test/e2e/site.spec.ts`): `test/serve.mjs` serves `dist/` under `/swarmcast/` like
  GitHub Pages; the tests cover the landing pages, light and dark mode, the language redirect and
  switcher, the download button and page per OS (with and without stats), the usage numbers, phone
  widths, alt text and keyboard focus. Run `npx playwright install chromium` once.

## Where things live

| Path | What |
|------|------|
| `src/content/docs/` | The guide pages in English (Markdown; one file per page) |
| `src/content/docs/pt-br/` | The same pages in Brazilian Portuguese, **same file names** |
| `src/pages/index.astro`, `download.astro` (+ `pt-br/`) | The custom landing and download pages (components in `src/components/`) |
| `src/lib/copy.ts` | All words of the landing and download pages, both languages (typed: a missing string fails `npm run check`) |
| `src/lib/i18n.ts` | Small UI strings of the components, and the path helpers |
| `src/lib/download.ts` | OS detection and which installer the download button offers (pure, unit-tested) |
| `src/lib/stats.ts`, `src/components/UsageStats.astro` | The usage numbers (see "Stats") |
| `astro.config.mjs` | Locales, sidebar (with the pt-BR labels), link validator, head tags |
| `src/brand.mjs` | The one place for branding on the site: logo files, favicon, mascot, and the public URLs (repo, releases) |
| `src/styles/` | `tokens.css` (brand tokens + fonts + layout scale), `ui.css` (the site's components), `starlight.css` (Starlight mapped onto the tokens) |
| `offline-guide.json` | Which pages, in which order, make the offline guide (`scripts/build/guide-html.mjs`) |
| `public/` | Files copied as-is (`favicon.svg`; `stats.json` is added at deploy time) |

Screenshots come from `docs/img/` at the repository root (regenerated by `scripts/docs/screenshots.mjs`)
and from `apps/admin/src/onboarding/img/`, referenced by relative paths in the pages.

## Languages (i18n)

English is the root locale (`/swarmcast/…`), Brazilian Portuguese is `pt-br` (`/swarmcast/pt-br/…`).
Every page must exist in both: the link validator fails the build on a link that points across
locales, and the sidebar labels have their translations in `astro.config.mjs`. When you add or rename a
page, do it in both folders and update the sidebar (and `offline-guide.json` if it belongs in the
offline guide).

On the first visit, a browser in Portuguese is sent to the pt-BR page (`src/lang-redirect.mjs`); after
that the last language read is remembered in `localStorage`, so the language switcher always wins.

## Brand

Colours, fonts, radii and shadows come only from the shared brand tokens,
[`assets/brand/tokens.css`](../assets/brand/README.md) (Forest & Cream, light and dark), imported by
`src/styles/tokens.css` and mapped onto Starlight's variables in `src/styles/starlight.css`. Never
hard-code a colour here; change the brand in `assets/brand/` and the site follows. `src/tokens.mjs`
reads literal values at build time for the browser's `theme-color` and the contrast test. The symbol,
mascot and favicon are the files from `assets/brand/` named in `src/brand.mjs`.

## Deploy

GitHub Actions builds, tests and deploys the site to GitHub Pages: pull requests that touch the site
(or the screenshots, the brand or the shared translations) are built and tested without deploying; a
merge to `main` with such changes deploys it. Pages must be set to **Source: GitHub Actions**
(Settings → Pages). Maintainer details: [docs/RELEASING.md](../docs/RELEASING.md#6-github-pages-and-usage-numbers).

## Stats

The site shows usage numbers **without telemetry**: the app never phones home. A daily job (and one
on every release) saves GitHub's public release download counters (installer downloads, and the
`latest.json` downloads that estimate "apps opened this week") to the orphan branch `stats`
(`scripts/stats/`). The deploy copies its `summary.json` to `public/stats.json`; without it the site
simply hides the numbers. The download button also uses it to link straight to the right installer of
the latest release (otherwise it opens the releases page). The "Privacy and usage numbers" page
explains this to visitors.
